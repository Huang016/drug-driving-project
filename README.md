# 第一部分：整體流程

```
A 警政 (403,088 件事故) ┐
B 檢驗 (50,000 件送驗)  ┼─ 三方 ECDH-PSI，交集 5,878 人 ─→ 可信第三方合併寬表 ─┬→ 去 ID、部分粗化 → PETsARD → 依法規修正 → 合成寬表（可公開）
C 監理 (11,756 人)      ┘   （各機構只送出交集，PQC 加密傳輸）                 └→ 依縣市／鄉鎮彙總 → 差分隱私 → 熱區圖（只公開加噪後的總和）
```

| 階段 | 做什麼 | 誰看得到原始資料 |
|---|---|---|
| 1. 三方 PSI | 三個機構用 ECDH-PSI 找出共同的人，只揭露交集 | 各機構只看得到自己的表 |
| 2. 加密傳輸 | 各機構只把交集者的資料，用 ML-KEM-768 + X25519 混合加密、ML-DSA-65 簽章後傳給可信第三方 | 傳輸途中沒有人看得到 |
| 3. 合併寬表 | 可信第三方用 PSI 產生的 `psi_token` 一對一合併 A、B、C | 只有可信第三方（受控環境） |
| 4. PETsARD 合成 | 寬表去 ID、粗化後合成，再用 PETsARD 評估效度、保真度、隱私風險 | 對外只公開合成資料 |
| 5. DP 熱區圖 | 用真實寬表依地區彙總，加上 Laplace 雜訊 | 對外只公開加噪後的數字 |

**與舊版規格書最大的不同：**

- **串接改用 PSI，不再用 `hashed_id` 比對。** 舊的 `hashed_id`（SHA256(公開鹽:6 位數 ID)）只有 10⁶ 種可能，幾秒內就能全部反查回去。目前 `hashed_id` 欄位只是保留下來，流程中不使用。
- **PETsARD 改為合成「三方合併後的寬表」**，依 PETsARD 官方的多表處理建議，先反正規化再合成，不再由三方各自合成。

# 第二部分：三方資料規格

## 1. 共用母體與編號

三張表用同一組 `master_id` 對齊，每個 `master_id` 代表同一個人（模擬身分證字號）。

```
B（檢驗，50,000 人，master_id 1–50,000）
 └─ 陽性 11,756 人 = 確定毒駕
     ├─ 50% 發生事故 → 也在 A（5,878 人）
     └─ 50% 路檢攔查、未肇事 → 不在 A（5,878 人）
C（監理）= 全部 11,756 位毒駕者的處分紀錄
A（警政）= 114 年全部傷亡事故 403,088 件；其中 5,878 件是上述毒駕者肇事
```

| 項目 | 數值 | 依據 |
|---|---|---|
| B 母體 | 50,000 人，`master_id` 1–50,000 | 專題設定 |
| B 陽性 | 11,756 人（23.5%），**視為確定毒駕** | 陽性率參考 FDA 全國送驗陽性率（約 23%） |
| 陽性者中發生事故的比例 | **50%**（5,878 人） | **假設值**（真實世界多數毒駕是路檢攔查，見第 7 節） |
| A 母體 | 403,088 件，等於 114 年全年傷亡事故 | 官方資料 |
| A 的其他事故當事人 | `master_id` 50,001–447,210 | 不在 B，也不在 C |
| C 母體 | B 陽性者全部 11,756 人 | 依規則：B 陽性 ∪ A 有前科（A 有前科者都在 B 陽性內） |
| **三方交集（寬表）** | **5,878 人**（毒駕且肇事） | |

## 2. 生成順序

```
第 1 步：B（使用者提供，50,000 筆，未改動）
第 2 步：A ← 讀官方事故資料與 B
         ・從原始事故中挑出 5,878 件毒駕事故，對應到 B 陽性者的 50%
         ・挑選條件：B 的檢驗日要在事故日後 0–3 天
         ・這 5,878 人的年齡層、性別改用 B 的值
第 3 步：C ← 讀 A 與 B，依 §35 判定處分
第 4 步：一致性檢查（datagen/validate_v3.py）
```

# 第三部分：寬表與合成資料

## 寬表

三方交集 5,878 人（毒駕且肇事）。路檢攔查的人沒有 A 紀錄，所以不在寬表中。

| 檔案 | 內容 |
|---|---|
| `wide_table_full.csv` | 合併後的完整資料，33 欄（含鄉鎮、經緯度，供熱區圖使用） |
| `wide_table_petsard_input.csv` | 實際餵給 PETsARD 的版本，15 欄 |

PETsARD 輸入版的處理：

| 處理 | 欄位 |
|---|---|
| 保留 | 縣市、精確小時、年齡層、性別、檢體、檢出物質、再犯次數、A1/A2 |
| 轉換 | 日期 → 月份 + 星期幾；車種 → 機車／小客車／貨車／大客車；受傷人數 4 人以上合併；檢驗日 → 事故後第幾天；處分日 → 天數區間；5 個處分欄位 → 一欄 `sanction` |
| 拿掉 | ID、鄉鎮、經緯度、精確日期；全部相同的欄位（`is_drug_related`、`test_result`、`detection_source`）；可由其他欄位推回的欄位（之後補回） |

## 合成資料

- **工具**：PETsARD 1.10.1，預設的高斯 Copula 合成器，Python 3.11
- **切分**：50/50，訓練組 2,939 人、對照組 2,939 人，重複 10 次；發布的是事先指定的第 1 次
- **結果**：`synthetic_wide.csv`，2,939 筆 × 24 欄
- **合成後處理**：依規則補回推導欄位；2,939 筆中有 797 筆（約 27%）處分不符合 §35，例如死亡事故卻只吊扣，已依規則修正

**為什麼用 50/50 而不是常見的 80/20：** 我們做了對照測試，拿完全沒有洩漏的資料去評估：訓練組和對照組一樣大時，指認風險測出 0.00；訓練組是對照組的 2 倍時，卻測出 0.13–0.17。所以 80/20 會系統性高估指認風險，採 50/50 才能公平評估。

## PETsARD 評估結果（10 次切分的平均）

| 指標 | 結果 | 官方建議門檻 |
|---|---|---|
| 資料效度 | 1.00 | ≈ 1.0 ✅ |
| 保真度 | 0.95 | ≥ 0.75 ✅ |
| 欄位配對相似度（補充，105 組） | 平均 0.95，最低 0.83 | — |
| 指認風險 singling out | 0.03（最差 0.06） | < 0.09 ✅ |
| 連結風險 linkability | 0.00（見下方說明） | < 0.09 ✅ |
| 推論風險 inference | 0.00（最差 0.03） | < 0.09 ✅ |

- PETsARD 的保真度只計算「真實資料中關聯夠強」的欄位配對，所以另外附上全部欄位配對的相似度作為補充。
- 指認攻擊設定 `max_attempts: 500000`，確保每次都能產生足夠的攻擊查詢；預設值太小時只能產生約 10 筆，風險會被低估。
- **連結風險為何是 0.00**：PETsARD 報表只顯示到小數點後兩位。以 anonymeter 直接重算（第 1 次切分）：
  | 設定 | 攻擊成功率 | 隨機猜測基準 | 對照組 | 風險 |
  |---|---|---|---|---|
  | 只猜 1 個最近鄰（PETsARD 預設） | 0.0013 | 0.0010 | 0.0010 | 0.0003 |
  | 猜 10 個最近鄰（較強攻擊） | 0.0319 | 0.0374 | 0.0329 | 0.0000 |

  隨機猜中的機率約為 1/2,939 ≈ 0.0003，攻擊者的成功率與隨機猜測相當，所以風險確實接近 0，評估本身是有正常執行的。
